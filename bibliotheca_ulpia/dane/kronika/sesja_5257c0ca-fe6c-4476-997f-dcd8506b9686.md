## 1. GitHub UI — najszybciej wzrokowo

## 2. CLI (to odpalimy w nowej sesji)
```bash
git fetch origin
# ile roboczy wyprzedza / jest za main (behind  ahead):
git rev-list --left-right --count origin/main...origin/claude/sleepy-fermi-dsdE4
# commity w roboczym, których NIE ma w main:
git log --oneline origin/main..origin/claude/sleepy-fermi-dsdE4
# commity w main, których NIE ma w roboczym (to sygnał prawdziwego rozjazdu):
git log --oneline origin/claude/sleepy-fermi-dsdE4..origin/main
# różnica plików:
git diff --stat origin/main origin/claude/sleepy-fermi-dsdE4
```

## 3. Jak to czytać
- **Roboczy „ahead", main „behind 0", zero commitów w main-nie-w-roboczym** → wszystko OK, po prostu jeszcze nie zmergowane. Zmergujesz PR → zgodne.

Najczęstsza przyczyna: zmergowałeś wcześniejszy PR przez **Squash merge** — wtedy main dostaje jeden „sklejony" commit o innym haszu niż pojedyncze commity roboczego, i git widzi rozjechanie mimo tej samej treści. Wtedy w nowej sesji zsynchronizujemy roboczy z main (merge `main` → roboczy).
