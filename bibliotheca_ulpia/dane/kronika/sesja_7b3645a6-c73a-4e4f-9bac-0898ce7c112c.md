## Co realnie znaczy „hybryda auto-dostosowująca się"

To jest **przełącznik zależny od reżimu rynku** — system rozpoznaje w jakiej fazie jest rynek i sam wybiera tryb/wagi/lewar. Nie „świadomość", tylko **warunkowa logika sterowana pomiarem**. Ale efekt z zewnątrz wygląda jak inteligentna adaptacja.

### Najlepsze: masz już POŁOWĘ tego w kodzie
Sprawdziłem — `legatus.py` już woła `klasyfikuj_rezim(wskazniki)` i masz `WAGI_REZIMU`. Czyli rój **już dziś** rozpoznaje reżim i zmienia wagi neuronów. Brakuje tylko, żeby reżim sterował **też** trybem, lewarem i progiem wejścia. To nie rewolucja — to dokończenie istniejącego mechanizmu.

### Jak wyglądałaby pełna hybryda

| Rynek rozpoznany | Co system robi automatycznie | Dlaczego (z naszych pomiarów) |

## Dlaczego mimo to radzę zacząć od kalibracji pewności

Hybryda reżimowa **potrzebuje** dobrze skalibrowanej pewności jako wejścia. Jeśli `pewnosc ≈ 1.0` zawsze, to przełącznik reżimowy i tak dostanie zafałszowany sygnał siły. Kolejność:

```
1. Kalibracja pewności   →  system wie JAK MOCNY jest sygnał (fundament)
2. Hybryda reżimowa      →  system wie W JAKIM RYNKU jest i dobiera tryb/lewar
3. Shapley/MRC (Faza 2)  →  wagi uczą się same z historii (pełna autonomia)
```

To nie są konkurencyjne opcje — to **trzy piętra tej samej wieży**. Hybryda to piętro 2, którego chcesz. Ale postawione na piętrze 1, inaczej się chwieje.

## 🏛️ Nasza lepsza wersja: WARSTWA BRAMKUJĄCA (Gating / „Namiestnik Reżimu")

Genialne jest to, że **mamy już prawie wszystkie klocki** — brakuje jednego mózgu, który je spina. Oto projekt:

```
                    ┌─────────────────────────────────┐
   bary ──────────► │  KLASYFIKATOR REŻIMU (mamy!)     │  ADX/zmienność/entropia
                    │  klasyfikuj_rezim()             │  → TREND / BOK / CHAOS / VOL
                    └───────────────┬─────────────────┘
                                    ▼
        ┌───────────────────────────────────────────────────────┐
        │      🧠 NAMIESTNIK (Gating Network — NOWY, deterministyczny) │
        │  Na podstawie reżimu DOBIERA AUTOMATYCZNIE:            │
        │   • tryb       (agregat / filtr / strategia)          │  ← łączy Klucznik!
        │   • wagi neuronów  (WAGI_REZIMU — mamy!)              │
        │   • lewar      (kalibracja pewności wg reżimu)        │  ← naprawia defekt
        │   • próg wejścia (wyższy w chaosie, niższy w trendzie)│
        │   • czy w ogóle grać (BOK 1H → stój z boku)          │  ← nasze straty 1H
        └───────────────┬───────────────────────────────────────┘
                        ▼
   Legatus (neurony) + Klucznik (strategie po kluczach) ─► Kalkulator ─► pozycja
```

### Jak to łączy WSZYSTKO o co prosiłeś
- **Strategia + klucze** → w reżimie „trend+zgodna strategia" Namiestnik włącza tryb `filtr` (Klucznik musi potwierdzić). W czystym trendzie → `agregat`. To **wreszcie wpina Klucznik w decyzję zależnie od rynku**.
- **Kalibracja pewności** → lewar liczony per-reżim (trend = pewniej, chaos = ostrożnie). Naprawia `pewnosc≈1.0`.
- **Auto-adaptacja** → jeden `Namiestnik.decyduj(rezim)` zwraca komplet ustawień. System sam się przełącza świeca po świecy.
- **Stój z boku** → reżim BOK/CHAOS na 1H = brak wejścia (nasze udowodnione straty znikają).

### Dlaczego nasza wersja LEPSZA niż rynkowe
1. **W pełni audytowalna** (Prawo I/XXI) — to deterministyczna tablica reżim→ustawienia, nie czarna skrzynka RL. Każdą decyzję da się wytłumaczyć.
2. **Mierzona, nie zgadywana** (Prawo XVI) — porównamy 12 backtestów: stary system vs Namiestnik.
3. **Bez lookahead** — mamy detektor który to gwarantuje.
4. **Gotowa pod Fazę 2** — Namiestnik to miejsce, gdzie później wstawimy Shapley/MoE-gating uczone online. Najpierw wersja deterministyczna (działa, tania), potem ucząca.
